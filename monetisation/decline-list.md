## 0. Read this first

1. **Authority.** The Ground rules in `BRIEF.md` section 3 win. The persona bibles' sections 9.2 (sponsors to decline) and 9.3 (brief red flags) and `rate-card.md` section 2 are the sources for the rows below. This file summarises them in one place. If this file and a bible disagree, **the bible wins and this file is corrected** (the same rule the media kits follow).
2. **Three classes of decision.**
   * **A, always decline.** A Ground rule, or a studio rule with no condition attached. Nobody's answer unlocks it; only the user could change a Ground rule, and a conflict with one is a reason to stop and ask (`BRIEF.md` section 3).
   * **B, decline by default.** The persona bible says to decline unless a named condition is met and documented (a lawyer clears it, or the brief is cut down to specification only). The condition is in section 5. If the condition is not documented, the answer is decline.
   * **R, rewrite or decline.** The sponsor is fine but the brief asks for something the studio does not do. Offer the rewrite once; if the brand will not take it, decline.
3. **When in doubt, stop.** If something feels wrong and is not listed, do not answer yes. Pause, ask the wife, then the lawyer. If the answer is ambiguous the answer is decline, the same rule the portfolio applies to the lawyer-gated slots (`strategy/portfolio.md` 2C row 9).
4. **Examples are generic types, not companies.** No brand, agency or person is named in this file. When a real sponsor is declined, its name goes only in the private decline log (section 6), never in the repo.
5. **How to decline.** One short, polite reply from the studio mailbox by a human (the mailbox does not exist yet; no address is invented here). No legal argument, no accusation, no naming of other clients, no promise to reconsider, no negotiation in a character's comments or DMs. Keep the reply and log it.
6. **Platform rule.** A character account never answers a sponsor. Business enquiries go to the studio mailbox and are answered by a person.
